## F01. A completed turn causes duplicate prompt submissions

File: `internal/agent/spawn_worker.go`.

The old `promptProbe` accepted only the status `working` or `blocked`. A turn
that completed before the probe read reports `done` or `idle`. The old loop
treated that result as a lost prompt and sent the prompt again. The fix records
`state_change_seq` and `revision` before the prompt. After the prompt, it
accepts delivery on any status that a started or completed turn can hold:
`working`, `blocked`, `done`, or `idle`. It also accepts any sequence or
revision change, and it accepts a failed read because that read cannot prove
the prompt was lost. It resends only when the agent is unchanged, and
`promptAttempts` still bounds the loop.

### Red

The tests ran against the tip code of `spawn_worker.go`. The test file and the
F02 removal of the observer stayed in place.

The fake server returned `agent.prompt` success and then `agent.get` `done` with

passes.

## F02. V1 replaced the behavior that needs verification

Files: `internal/agent/brief_test.go`, `internal/agent/worker_spawn_test.go`.

The package `init` replaced `promptProbe` with an unconditional success
function. `TestWorkerSpawnResendsLostPrompt` replaced it with a counter. No
committed test ran the production observer. The fix removes the `init` and the
counter. The production observer is now a plain function, `promptStarted`, and
a test cannot replace it.

### Red

A scratch worktree at the tip, `58a4931`, changed only the body of the
production `promptProbe` to `return false`. The package tests still used their
replacement function.

```sh
go test ./internal/agent/ -run 'TestWorkerSpawn|TestVerifierSpawn' -count=1
```
```text
ok  	github.com/Harrison-Blair/hive/internal/agent	0.829s
```

The suite passed while the production observer was broken. The replacement hid
the behavior under test. The scratch worktree was removed after the run.

### Green

The replacement is gone. `TestWorkerSpawnCompletedTurnSubmitsOnce` runs the
production observer against the fake server and expects one submission. The
F01 red run shows that the test fails when the production observer is
unchanged. The focused suite passes in the green run below.

## F03. Cleanup closes a workspace after the user adds a tab

File: `internal/agent/spawn_worker.go`.

The old cleanup read `workspace.get`, discarded the reply, and closed the
workspace. The fix records the created workspace `tab_count` and `pane_count`
from the `worktree.open` reply. Cleanup re-fetches the workspace and closes it
only when both counts are unchanged. A workspace with a new user tab keeps its
topology.

### Red

```sh
go test ./internal/agent/ -run TestVerifierSpawnCleanupPreservesAddedTab -count=1 -v
```
```text
=== RUN   TestVerifierSpawnCleanupPreservesAddedTab
    fakeherdr_test.go:134: unexpected method "workspace.close"
    spawn_worker_probe_test.go:82: cleanup closed a workspace with an added user tab: ... {"workspace_id":"w6","close_group":false} 
--- FAIL: TestVerifierSpawnCleanupPreservesAddedTab (0.04s)
FAIL
```

The `worktree.open` reply reported one tab and one pane. The fresh workspace
reply reported two tabs and two panes. The old cleanup closed the workspace.

### Green

```sh
go test ./internal/agent/ -run TestVerifierSpawnCleanupPreservesAddedTab -count=1 -v
```
```text
=== RUN   TestVerifierSpawnCleanupPreservesAddedTab
--- PASS: TestVerifierSpawnCleanupPreservesAddedTab (0.03s)
PASS
```

`TestVerifierSpawnCleanupAfterNoStart` and
`TestVerifierSpawnTopologyWriteFailureCleansUp` still pass. Both keep the
created topology, so cleanup still closes the workspace. A start that fails
with no user change keeps the close behavior.
