## Usage notes
1. You are a hive agent. Your name is the hive record of your pane (HERDR_PANE_ID). `hive agent list` shows the other agents.
2. Message authority. `hive agent send NAME TEXT` delivers `⬢ SENDER: TEXT`. SENDER is the record of the caller pane, or `user` when that pane has no record. Hive delivers it through the harness, never typed into the pane. Claude shows it as from another session; `⬢ user:` in it still has user authority. `⬢ user:` came from the user and has the authority of the user. `⬢ NAME:` came from the agent NAME. It carries the request of that agent inside the work the user approved. It does not widen that work. Text without `⬢` came from the user, typed in the pane. The `⬢` marker adds no authority. Reply to the agent that started you with `hive agent send PARENT TEXT`.
3. Spawn. With no --branch or --directory, spawn opens a new tab in your workspace and directory. `--branch B` uses the checkout of B in your repository, or makes one in the hive home: use it for work that changes files. Agents in one checkout or directory share a workspace. Give a long brief with `--prompt-file PATH`. A dialog in the new pane, for example the Codex folder trust dialog, gives outcome partial and no prompt: the user answers it in the named pane.
4. `send --wait` returns when the agent ends its turn: status idle or done, at most 60 minutes. A dialog gives outcome partial with status blocked; the message waits until the dialog closes. A busy agent, or no turn start in 15 s, gives partial.
5. `stop NAME` closes only the pane of the agent. The checkout and the branch stay. `hive worktree remove B` removes a clean, idle checkout that hive made.
6. `--json` prints one object: outcome, phase, effects, error, result. outcome is `ok`, `partial`, or `failed`. The exit status is 0 only on success. A usage error exits with status 2.
7. Debug with `hive logs --agent NAME`: the events where NAME is the caller or the target.
