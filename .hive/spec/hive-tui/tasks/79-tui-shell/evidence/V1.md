## Repair 1

Both slow-load tests now run the data commands returned by a second tick while
the first load is blocked. The header test keeps the Logs screen selected so
the tick command returns a batch; the test runs the load commands and checks
that the header loader starts once. The screen test does the same for the
screen loader. Both tests also send screen keys while a load is blocked.

The brief ratchet found passive-voice sentences across two runs. I changed
“Its decisions are approved” to “The README approves each decision”,
“`cmd/root_test.go` is now in the source table” to “Scope change 1 adds
`cmd/root_test.go` to the source table”, and “the `headerLoading` guard is
removed” to “code removes the `headerLoading` guard”.

- With the `headerLoading` guard changed to `if false`,
  `go test ./internal/tui -run '^TestSlowHeaderLoadDoesNotBlockKeysOrStartTwice$' -count=1`
  failed because the refresh started a second header load.
- With the `screenLoading` guard removed,
  `go test ./internal/tui -run '^TestSlowScreenLoadDoesNotBlockKeysOrStartTwice$' -count=1`
  failed because the refresh started a second screen load.
- After restoring both guards,
  `go test ./internal/tui -run 'TestSlow(Header|Screen)LoadDoesNotBlockKeysOrStartTwice' -count=1`
  passed.
