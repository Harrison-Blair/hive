# V1: Chat noise levels

## Event mapping

- `all` shows `message`, `completed`, `verified`, `blocked`, `exited`, `quiet`, and `unresolved` inbox records.
- `landings and decisions` shows `completed` and `verified` records as landings, and `message` records as decisions.
- `decisions only` shows `message` records.

The inbox schema has no `decision` record kind. The filter uses `message` records for decisions.

## Test-first result

Before the code change, this test failed:

```text
go test ./internal/tui -run '^TestChatNoiseLevelsFilterInboxKinds$' -count=1
```

It showed `noise: messages` and failed to find `noise: landings and decisions`. This is the expected failure on the base code.

After the code change, the same command passed:

```text

```

The test checks all three levels and the `n` cycle with model `Update` and `View` calls. It checks each expected event with a literal string.
