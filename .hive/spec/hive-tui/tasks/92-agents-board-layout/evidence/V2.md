## Differences from the board and their causes

- The board sample has ten agents and different task data. The copied home has eight live agents, two open-task ghosts, and three project groups. The live counts and labels come from the copied records.
- The sample selects a worker. The screen starts with the coordinator selected, so its detail strip has `?` for fields that the coordinator does not have. The selected worker in the scrolled 120 x 40 capture has its own details.
- Old manager records have no explicit parent field. G4 makes those lineage edges inferred, so the graph labels them `inferred`.
- At 120 x 40 the graph is wider than the panel. The default capture keeps the selected coordinator in view. The extra capture shows the selected manager after the view scrolls to the right. The panel clips the other columns at its boundary; no rendered line runs past the terminal edge.
- The 120 x 40 detail strip wraps to two rows. The table uses ellipses for long values. Both changes keep the frame within the available width.
- The design uses a fixed time and fixture labels. The captures show the copied home's current ages, project title, task names, and status counts.
- The footer shows the Chat guard notice `rule 2 (working directory is below projects/)`. The pane runs from the task worktree. I did not open the Chat input or press Enter.
- These initial captures have the edge legend but no dashed nudge edge. At capture time, the graph did not load inbox records. The manager has now specified the read-only inbox rule; V2 will be updated after that change and a new green run.
- `herdr pane read` used text format, which strips terminal color. The golden frame tests check layout and content. Selected items use the honey-bold style and `▶` marker in the running TUI, with no background fill.

## Supervisor-row gap cause

The old load path passed only a supervisor-live boolean to `agentStatus`. That check made a live supervisor record display as `unknown` when its lifecycle data did not include an `agent_status`. The old graph also had no claim PID fallback and used only `status_changed_at` for age. The real `hive agent show supervisor` result reports generation 16 as `live` in `wBC:p19` and provides `started_at`; it does not print a PID. The change reads the matching supervisor claim for its PID, uses the lifecycle record for status while the claim is fresh, and uses `started_at` when `status_changed_at` is empty. The live graph capture shows the supervisor PID and age.
