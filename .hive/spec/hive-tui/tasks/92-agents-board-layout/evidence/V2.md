## Differences from the board and their causes

- The board sample has ten agents and different task data. The copied home has eight live agents and three project groups. No stopped agent met the ghost rule in this snapshot, so the board sample's ghost node does not appear. The live counts and labels come from the copied records.
- The sample selects a worker. The screen starts with the coordinator selected, so its detail strip has `?` for fields that the coordinator does not have. The selected worker or manager in the scrolled 120 x 40 capture has its own details.
- Old manager records have no explicit parent field. G4 makes those lineage edges inferred, so the graph labels them `inferred`.
- The added inbox fixture has one unread record with `NudgedAt` set for `manager-hive`. Both default GRAPH captures show one dashed edge: `supervisor ┄┄▶ manager-hive · nudge`. Read records and records without `NudgedAt` produce no edge in the fixture tests. Workers and verifiers produce no nudge edge.
- At 120 x 40 the graph is wider than the panel. The default capture keeps the selected coordinator in view and shows the nudge edge. The extra capture shows the selected manager after the view scrolls to the right. The panel clips other columns at its boundary; no rendered line runs past the terminal edge.
- The 120 x 40 detail strip wraps to two rows. The table uses ellipses for long values. Both keep the frame within the available width.
- The design uses a fixed time and fixture labels. The captures show the copied home's current ages, project title, task names, and status counts.
- The footer shows the Chat guard notice `rule 2 (working directory is below projects/)`. The pane runs from the task worktree. I did not open the Chat input or press Enter.
- `herdr pane read` used text format, which strips terminal color. The golden frame tests check layout and content. Selected items use the honey-bold style and `▶` marker in the running TUI, with no background fill.

## Supervisor-row gap cause

The old load path called `supervisorIsLive` only to get a boolean for the generic `agentStatus` mapper. The supervisor lifecycle record was `live` but had no `agent_status`, so the generic mapper returned `unknown`; the claim PID did not fill that status. The old graph also had no claim PID fallback and used only `status_changed_at` for age. The real `hive agent show supervisor` result reports generation 16 as `live` in `wBC:p19` and provides `started_at`; it does not print a PID. The change reads the matching supervisor claim for its PID, uses the lifecycle record for status while the claim is fresh, and uses `started_at` when `status_changed_at` is empty. The live graph capture shows the supervisor PID and age.
