# V2: Idle CPU

I built the base binary from `ef2dde2e` and the task binary from this task branch. I ran both in a herdr pane in the worker workspace. Each run used a temporary copy of a marked home, a temporary `XDG_CONFIG_HOME`, and these variables removed: `HERDR_ENV`, `HERDR_PANE_ID`, `HERDR_WORKSPACE_ID`, and `HERDR_SOCKET_PATH`. I selected each screen before the 60-second idle interval. I sent no input during that interval. I measured each process with `ps -o %cpu=,etime=,comm=`.

| Screen | Base CPU | Task CPU |
| --- | ---: | ---: |
| Chat | 11.4% | 0.3% |
| Agents | 1.2% | 0.2% |
| Goals | 0.9% | 0.1% |
| Queue | 0.9% | 0.2% |
| Tasks | 0.7% | 0.2% |
| Friction | 0.7% | 0.2% |
| Health | 1.9% | 0.8% |
| Logs | 16.0% | 1.2% |

The base Chat profile ran for 60.36 seconds and sampled 7.58 CPU seconds (12.56%). Its hot path was repeated `View` and `shellView` work. `chatView` and `chatEventsView` triggered ANSI string-width and grapheme scans.

The base Logs profile ran for 60.33 seconds and sampled 7.35 CPU seconds (12.18%). Its hot path included `logs.readBoundedLine`, JSON decoding, maps, and garbage collection. The tick reloaded the daily log data each time.

The fix checks file-tree signatures in a background command. It starts a header or screen load only when its inputs change. Health still refreshes every four seconds. The TUI also caches the screen panel and whole view. A minute change replaces the header only.

A task Chat profile after the fix sampled 130 ms over 60.14 seconds (0.22%). All task binary screen measurements were below 2%.
