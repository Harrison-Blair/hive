# V3 Startup Smoke Test

**Result: the tab and record checks passed with a manual Pi startup workaround.** The second automatic Pi start did not complete.

The test used a temporary home and XDG config in isolated Herdr session `hive-stale-coordinator-v3-pi-20261021`, workspace `w1`. The coordinator config was:

```toml
home = "/tmp/hive-stale-coordinator-pi.y9V3Ms/home"

[coordinator]
harness = "pi"
model = "opencode-go/deepseek-v4.1-flash:medium"
```

## First run

The task binary created `coordinator` tab `w1:t2` and `supervisor` tab `w1:t3`. Pi showed no project-trust or login prompt. The automatic startup prompt first returned `agent_not_ready` while Pi was still launching. After Pi settled, I sent the same startup prompt once with Herdr. The coordinator startup completed and registered `coordinator-g1`. `supervisor-g1` was also present. Both records had `started_by_hive: true`.

I quit the TUI and closed the coordinator pane `w1:p2` by hand.

## Second run

The task binary made a new `coordinator` tab, `w1:t4`. It marked `coordinator-g1` stale and kept its record file. The automatic Pi start returned `agent_pane_busy`.

After the pane returned to a shell, I started Pi there with Herdr. It showed no trust prompt. Its startup prompt returned `agent_prompt_stalled`; I did not retry it. I stopped Pi and confirmed that the Hive-created tab still had `HIVE_STARTUP_ROLE=coordinator` and `HERDR_PANE_ID=w1:p4`. I then ran `hive agent register --role coordinator` in that tab. This created `coordinator-g2` with `started_by_hive: true`.

The final tab list was `hive` (`w1:t1`), `supervisor` (`w1:t3`), and `coordinator` (`w1:t4`). The agent records were:

- `coordinator-g1`: `stale`, file exists, `started_by_hive: true`.
- `coordinator-g2`: `live`, `started_by_hive: true`.
- `supervisor-g1`: `live`, `started_by_hive: true`.

The second run proved that a gone recorded pane does not block creation of a new coordinator tab, that the old record becomes stale and stays on disk, and that registration in the new Hive-created tab records the startup mark. The second Pi process did not complete coordinator startup; `coordinator-g2` was registered manually after the Pi prompt stalled.

I stopped the test processes, closed workspace `w1`, stopped and deleted the isolated Herdr session, and removed the temporary home, config, and binary.
