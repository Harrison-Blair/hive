# V2: Scratch-home CLI check

Built the task binary with `go build -o "$scratch/bin/hive" .`. Ran it with a temporary `HIVE_HOME` and temporary `XDG_CONFIG_HOME`. The fixture project used a temporary Git repository with base `dev` and a temporary bare `origin`. The three verified task records were fixtures in that scratch home.

Results:

- `task cancel --task 1-no-delivery --reason 'not needed'` exited 0. The record changed to `cancelled` and stored `not needed`.
- `land --task 2-already-base --mode merge --grant fixture` exited 0. Text included `branch was already on the base` and `already-merged merge <branch-tip>`. The record's delivery commit matched the task branch tip, `pushed` was true, the `dev` tip did not change, and origin received that base tip.
- `task cancel --task 3-landed --reason 'must refuse'` exited 1 with `hive: task is landed: cancel refused`. A SHA-256 comparison confirmed that the task record did not change.

The temporary home, config, repository, origin, and binary were removed by the check's exit trap.
