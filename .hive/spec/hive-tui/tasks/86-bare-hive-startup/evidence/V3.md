# V3 — live startup

**Setup.** I built the task binary. I used a temporary `HIVE_HOME` and a temporary `XDG_CONFIG_HOME`. The temporary config set `coordinator.harness = "claude"` and `coordinator.model = "claude-haiku-4-5"`. I created new herdr workspace `wNJ` in the task worktree.

**First run.** The TUI showed:

```text
⬢ hive · 0 projects · 2 live agents · 1 working / 1 idle · supervisor fresh
coordinator: live · unknown harness · working · wNJ:p2
```

`herdr tab list --workspace wNJ` showed exactly three tabs:

```text
wNJ:t1 hive
wNJ:t2 coordinator
wNJ:t3 supervisor
```

The temporary home had live records `coordinator-g1` and `supervisor-g1`. The coordinator pane ran `claude --dangerously-skip-permissions --model claude-haiku-4-5`. The supervisor pane ran `hive supervise` from the temporary home.

I quit the TUI with two `ctrl+c` keys. The root pane returned to its shell. The coordinator pane still ran Claude, the supervisor pane still ran `hive supervise`, and both records remained live.

**Second run.** I ran the same binary in the root pane. The screen showed `2 live agents` and `supervisor fresh`. The tab list still had the same three tab IDs and labels. The agent list still had only `coordinator-g1` and `supervisor-g1`; no new tab or agent was created. The coordinator pane still showed `live · unknown harness · done`.

I quit the second TUI with two `ctrl+c` keys. Both the Claude coordinator and `hive supervise` process remained in their panes.

**Cleanup.** I closed workspace `wNJ` and removed its temporary home, config, binary, and scratch files. I verified that the workspace and its agents were gone. The real home still had its pre-existing coordinator `coordinator-g6` and supervisor `supervisor-g13`; the supervisor PID and start time still matched. I also closed the exploratory test workspaces and removed their scratch files. The worker workspace has only its original task tab.

An earlier exploratory run used the main checkout's older coordinator skill and created a temporary `logs` tab. I closed that workspace and removed its scratch data. The final run above used the task worktree skill and created only the three expected tabs.
