# V3 — live startup

**Setup.** I built the task binary. I used a temporary `HIVE_HOME` and a temporary `XDG_CONFIG_HOME`. The temporary config set `coordinator.harness = "claude"` and `coordinator.model = "claude-haiku-4-5"`. I created new herdr workspace `wN9` in the task worktree.

**First run.** The TUI showed:

```text
⬢ hive · 0 projects · 2 live agents · 1 working / 1 idle · supervisor fresh
coordinator: live · unknown harness · working · wN9:p2
```

`herdr tab list --workspace wN9` showed exactly three tabs:

```text
wN9:t1 hive
wN9:t2 coordinator
wN9:t3 supervisor
```

The temporary home had live records `coordinator-g1` and `supervisor-g1`. The coordinator pane ran `claude --dangerously-skip-permissions --model claude-haiku-4-5`. The supervisor pane ran `hive supervise` from the temporary home.

I quit the TUI with two `ctrl+c` keys. The root pane returned to its shell. The coordinator pane still ran Claude, the supervisor pane still ran `hive supervise`, and both records remained live.

**Second run.** I ran the same binary in the root pane. The screen showed `2 live agents` and `supervisor fresh`. The tab list still had the same three tab IDs and labels. The agent list still had only `coordinator-g1` and `supervisor-g1`; no new tab or agent was created.

I quit the second TUI with two `ctrl+c` keys. Both the Claude coordinator and `hive supervise` process remained in their panes.

**Cleanup.** I closed workspace `wN9` and removed its temporary home, config, binary, and scratch files. I verified that the workspace and its agents were gone. The real home still had its pre-existing coordinator `coordinator-g6` and supervisor `supervisor-g13`; the supervisor PID and start time still matched.

An earlier exploratory run used the main checkout's older coordinator skill and created a temporary `logs` tab. I closed that workspace and removed its scratch data. The final run above used the task worktree skill and created only the three expected tabs.
