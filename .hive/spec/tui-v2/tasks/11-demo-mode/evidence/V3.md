# V3 Schema review

Proves AC1 and AC2. The schema types are in `internal/tui/demo.go` (`demoFixture` and the types below it). The loader uses `DisallowUnknownFields`, so an unknown field fails with an error that names the field (V1).

## Schema

| Field | Type | Holds |
| --- | --- | --- |
| `board` | string | The board file that the fixture copies. |
| `terminal` | `{width, height}` | The pane size of the board. The `--size` flag sets the draw size. |
| `clock` | `{time, zone}` | The fixed clock. `time` is RFC 3339. `zone` is an IANA zone. |
| `home` | string | The home path that the header shows. |
| `data.supervisor` | `{live, agent, pid, binary_old}` | The supervisor claim and the binary age that the header and Health use. |
| `data.projects`, `agents`, `goals`, `tasks` | store records | The same record types that the store reads. |
| `data.inbox` | map of agent name to inbox records | Unread and nudged messages. |
| `data.evidence` | map of task ID to file names | The evidence list of each task. |
| `data.friction` | list of `{file, resolved, title, status, opened, decision, body}` | Friction entries. |
| `data.checks` | doctor checks | Health checks. |
| `data.chat` | chat entries | The chat transcript. |
| `data.logs` | list of JSON objects | Log events. Each item must be a JSON object. |
| `ui.screen` | `agents`, `chat`, `work`, `friction`, `health`, `logs` | The active screen. |
| `ui.view` | per screen: work `goals`/`queue`/`tasks`, friction `open`/`resolved`, health `home`/`agents` | The view of the screen. |
| `ui.focus` | `graph`, `feed`, `input`, `list`, `details`, `filter`, `events`, `json` | The focused region. |
| `ui.selection` | string | The key of the selected row or card. |
| `ui.scroll` | map of region to `{top, left}` | The scroll position of each region. |
| `ui.filter` | `{open, text}` | The filter line and its text. |
| `ui.overlay` | `""`, `details`, `help` | The open overlay. |
| `ui.popup` | `""`, `agent-details` | The open popup. |
| `ui.prompt` | `{kind, target}`, kind `""` or `restart` | The open confirmation prompt. |
| `ui.hide_stopped` | bool | Agents and Health Agents hide stopped agents. |
| `ui.stops_only` | bool | The Queue view shows only stops. |
| `ui.follow` | bool | Logs follows the newest event. |
| `ui.log_day` | `YYYY-MM-DD` | The day that Logs shows. |
| `ui.chat_noise` | `""`, `quiet`, `normal`, `all` | The chat noise level. |
| `ui.chat_input` | string | The text in the chat input. |

## Decisions

- The v1 screens are still in place. The demo feeds them through the same build functions as normal mode. `applyDemoUI` applies the fields that the v1 screens have: `screen`, `view`, `focus`, `selection`, `hide_stopped`, `stops_only`, `follow`, `log_day`, and `chat_input`. The other UI-state fields (`scroll`, `filter`, `overlay`, `popup`, `prompt`, `chat_noise`) are parsed and checked and kept in the fixture for the wave 5 and 6 screen tasks.
- A fixture holds no file body for the task brief or the evidence files. Opening one of these files in demo mode reads the file from the home, as in normal mode.
- The README section `Manager decisions` records the demo loader file and the schema fields.
