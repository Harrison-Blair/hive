## Repair after the verify fail (t11-verifier-1)

The verifier found that demo mode read the live task brief and evidence files (`task_screen.go`, `startTaskFileRead`). A search of `internal/tui` for `os.ReadFile`, `os.Stat`, and `os.ReadDir` found two more paths that a demo screen can open: the friction entry (`startFrictionFileRead`) and the goal design (`o` on Goals, an `os.Stat` and a read of the feature `README.md`). The repair covers the three paths.

- The fixture field `data.files` holds the text of each file that a screen can open. The key is the path relative to the home or to a project directory.
- `readScreenFile` in `demo.go` reads the live file in normal mode. In demo mode it reads only `data.files`. When the fixture has no text for the file, the screen shows `demo mode: no file` in the file view and as the notice.
- The goal design check does not call `os.Stat` in demo mode.
