## How a mask check finds a title, a label, or a key hint

`Compare` validates each mask against the expected grid before it compares a cell.
A mask fails the compare when one of its cells in the expected grid has:

- a rune of the Unicode box-drawing block, U+2500 to U+257F. This block holds
  each border and scroll mark symbol of decision 13: `─ │ ╭ ╮ ╰ ╯ ├ ┤ ┼ ┴ ┬ └ ━ ┃`.
- the token `accent`. Decision 26 gives `accent` to titles, the focused
  border, the selection, and the active tab. Decision 4 gives it to the
  footer `[region]` tag.

`TestCompareRejectsBadMask` covers a left and a right border rune, an accent
title, a mask outside the grid, and a mask of width 0.

Limits:

- A label or a key hint in `dim` is not found. The check cannot tell a `dim`
  label or hint from `dim` data such as a time. Decision 45 requires user
  approval for each change to a mask file. That approval is the control for
  this case.
- A border cell that is a space, for example the padding inside a panel, is
  not found. Only the rune tells a border.
- A title in a token other than `accent` is not found.
- The check reads the expected grid only. A masked cell of the actual grid
  can hold a border rune. The token and bold compare still apply to it.

## Converter limits

- Each row of text must fit the grid. A row that is wider, or more rows than
  the height, fails. The live check must crop the pane read before it
  converts, or a later task must add a crop.
- The converter accepts only SGR codes `0`, empty, `1`, `22`, `39`, and
  `38;2;R;G;B`. Each other SGR code fails, also italic and underline. A colon
  form such as `38:2::R:G:B` fails, because a colon ends the parameter run
  and the sequence is then not SGR.
- A rune that `lipgloss.Width` does not measure as 1 fails, also a
  zero-width rune.
