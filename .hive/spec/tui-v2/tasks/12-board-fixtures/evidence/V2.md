# V2 Fixture review

Proves AC1. This file gives the source line of each value group, for each of the 19 new fixtures. Line numbers are in the board copy `.hive/spec/tui-v2/design/<Board>.dc.html`. The two Chat boards are the exception (see "Chat source").

## Rules that apply to each fixture

- Each fixture has the schema of task `11-demo-mode`. No schema change.
- `data` holds records in the format that hive stores. A board shows a rendering of these records. Where a board shows a short form of a stored value, the fixture holds the stored value, and the table names the short form. Example: the Health board shows `2.43.0`, and the check detail is `git version 2.43.0`, as `hive doctor` gives it. Decision 37 needs this: demo mode and normal mode use the same renderers, and normal mode gets the stored values.
- When a board shows text that is not a short form of a stored value, the fixture holds the board text. Example: the friction title `Bare hive in a scratch home starts real tabs`.
- The base records come from `Main.fixture.json`: the project `hive`, `coordinator-g2`, `supervisor-g4`, `manager-hive-g2`, `t4-worker-1`, `t4-verifier-1`, goal `g1-tui-restart`, task `4-agents-equal-columns`, and `data.supervisor`. Tasks `2-stale-coordinator-startup` and `3-tui-restart` use the real merge commits `0e079272…` and `3ccd93fb…` from `git log`.
- The header of each board shows `coordinator ● working`, `supervisor ● live`, and the clock `14:22`. Thus each fixture has `coordinator-g2` with `agent_status` `working`, `data.supervisor.live` true, and `clock.time` 14:22 UTC. `needs you` is 0 unless the table gives another value.
- The time zone of each clock is `UTC`, as in `Main.fixture.json`.

## Decisions for the screen tasks

- **Chat feed scroll:** `ui.scroll.feed.top` counts feed items (chat entries and folded events in time order) above the first visible item. This gives `↑ 42 earlier` in Chat.
- **Logs event scroll:** `ui.scroll.events.top` counts events above the first visible event.
- **Logs selection:** the key of an event is its `time`.
- **Friction seen:** the count of dated lines in the `Occurrences` section. An entry with no such section has a count of 1. The last date of the section gives `last`.
- **Friction body:** the bodies of the selected entries are wrapped at 62 cells, the width of the board text. The sections are `**Name:**` lines, as in the real entries.
- **Queue stop:** the WorkQueue stop of `1-cp5-end-to-end` comes from its unresolved acting agent. The task has no `needs_user`, so the header shows `needs you 0`.
- **Tab label:** the board tab label is the agent name. The schema has `tab_id` only.

## Board inconsistencies (recorded, not changed)

These come from the boards. The fixtures keep the board values. I report them to the manager.

1. **Times after the clock.** The clock is 14:22 on each board. Chat has a user message at 14:24. Logs shows events to 14:45:01. AgentDetails RECENT shows 14:44 to 15:08. The fixtures keep these times.
2. **HealthAgents stopped count.** The title `h hides 2 stopped` disagrees with its list (1 stopped agent of 5) and with CompactHealth (`h hides 1 stopped agent`). The fixture has 5 agents and 1 stopped agent.
3. **Logs agent filter.** The filter is `agent:manager-hive`, but the shown events include `t2-worker-1`, `t2-verifier-1`, and `t2-verifier-2`. Each event has the `agent_id` of its actor. The Logs screen task must decide whether `agent:` also matches the agents that a manager spawned.
4. **AgentsMany goal IDs.** The board shows `[goal]` for example-api and example-docs. Both goals have the ID `[goal]`. Two goals with one ID are not valid in the store.
5. **Coordinator pane.** CompactHealth shows `w58:p4`, and Main has `w58:p3`. The Health check `herdr pane` also shows `w58:p4`.
