## Repair: wrapped input cursor (verify fail of 885b4863)

**Result: pass.** The verifier found that the shown cursor did not follow the insertion point after Left in a wrapped input.

Cause: two wrap rules. The Input component wrapped the text with `wordWrap` at `width-6` cells. The textarea gave its cursor in its own wrapped rows: `SetWidth(width-6)` kept the two-cell prompt inside the width, so it wrapped at `width-8`. The textarea also keeps the space after each word in a row, so it puts fewer words on a row than `wordWrap`. The renderer used the textarea cursor X and Y on the component rows, so the two did not agree.

Fix (commit `60969662`):

- `internal/tui/component/input.go`: the Input takes the cursor as a line of the text and a rune column (`CursorLine`, `CursorColumn`) from `textarea.Line()` and `textarea.Column()`. The new `inputCursor` finds the wrapped row and the cell column of that point in the rows that the component shows. The board text and the wrap stay the same.
- `internal/tui/chat.go`: passes `Line()` and `Column()`. `SetWidth(width-4)` makes the textarea rows for up and down `width-6` cells, as the component rows.
- `internal/tui/tui.go`: removes the three cursor fields that this task added. The new code does not use them.
