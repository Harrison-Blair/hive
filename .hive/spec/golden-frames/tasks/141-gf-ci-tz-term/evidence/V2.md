# V2 TERM, red and green

Proves: AC2.

## Cause

The old test required the hide-cursor sequence `\x1b[?25l`. Whether the TUI
writes it depends on the input focus, not on `TERM`. In a checkout below
`projects/`, the TUI blocks the caller, the input has no focus, and the
cursor stays hidden. In any other checkout (a new clone, CI), the input has the
focus and the TUI shows the cursor, so the output has no `\x1b[?25l`. The base
passes in this worktree with each `TERM` and fails in a new clone with each
`TERM`. The CI log of run 40052654140 shows the same output: the frame is
present, `\x1b[?25l` is not.

## Fix

`cmd/root_test.go`: the test requires that the output enters the alternate
screen (`\x1b[?1049h`) and later leaves it (`\x1b[?1049l`), and that the
status row of the Chat frame (` ○ none · ○ supervisor · ? 0 asks · needs you 0`)
is between the two. It still checks status 0 and no `"outcome"` envelope.
The expected status text has no trailing space: with `xterm-256color` the
renderer writes a run of blanks as an erase sequence.
