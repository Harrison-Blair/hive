# V2: Task feature commands

Command-level integration test:

```sh
go test ./cmd/task -run '^TestFeatureTaskCLIFlow$' -count=1
```

Result: PASS. The test sets temporary `HIVE_HOME` and `XDG_CONFIG_HOME` paths,
registers a temporary Git project, and commits the feature README to its base
branch.

The test checks these command behaviors:

- Create without `--feature` fails in `validate` and writes no task, brief, or
  counter.
- Create with `--feature f` and no base README fails in `validate` and names
  `.hive/spec/f/README.md`.
- `--spec` skips the README check and stores `spec: true`.
- A normal feature task succeeds after the README commit.
- A 40-character feature slug succeeds. Uppercase, double-hyphen, and
  41-character slugs fail validation.
- `task list --feature f` returns both `f` tasks and excludes tasks of other
  features.
- `task show` prints feature paths. It warns about missing linked briefs and
  READMEs in text and JSON. An active worktree check uses its own files.
- A controlling manager can assign a feature to an old task in `verified`
  status. A worker cannot do this. The command rejects both edit flags and
  refuses a second feature assignment.
