## Bug

`reuseManagerWorkspace` in `internal/agent/workspace.go` compared the pane cwd
and the tab membership but not the pane ID. A moved root that returned to the
first tab with a new current pane ID passed the checks. The spawn then started
the manager in the unrecorded pane.

## Fix

`reuseManagerWorkspace` now refuses when the `pane.get` reply returns a pane ID
that differs from the recorded root. The refusal is
`workspace <id> has no recorded root pane: pass --pane <shell pane>`. The
recorded workspace metadata stays, and no `agent.start` is sent.
