## Scope

This item records the red and green runs of the identity fix. The fix is in
`internal/agent/spawn.go`. The test is
`internal/agent/capture_identity_test.go`.

The amended T19 brief closes finding B01 of the verification report
`t19-verify-01.md`: the spawn core selects a foreground candidate by
`entry.Name` only, so it rejects the wrapper launcher that Cursor starts. The
fix also selects a candidate when the base name of `*entry.Argv0` or the base
name of `entry.Argv[0]` is in the profile `ProcessNames()`.

## Change under test

`captureIdentity` selects one foreground entry when one of these is a profile
process name:

- `entry.Name`
- the base name of `*entry.Argv0`
- the base name of `entry.Argv[0]`

Two matching entries return
`multiple foreground processes have a profile name`. No matching entry returns
`no foreground process has a profile name`. The other checks stay the same.

## Test

```sh
go test ./internal/agent/ -run 'TestCaptureIdentityArgvMatch' -v -count=1
```

The test uses a real live process for the positive cases, because the identity
function reads the process start time from `/proc/PID/stat`. The negative and
multiple cases stop before the process read.

The subtests are:

- `argv0 selects a wrapper launcher`: name `MainThread`, argv0 `cursor-agent`.
- `argv0 with a path selects a wrapper launcher`: argv0
  `/home/penguin/.local/bin/cursor-agent`.
- `argv with a path selects a wrapper launcher`: name `MainThread`, argv[0]
  `/home/penguin/.local/bin/cursor-agent`.
- `no name or argv match is rejected`: name and argv `node`.
- `two matches are multiple`: one name match and one argv match.
